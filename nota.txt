DESCRIPTION
The SLSTR Level 2 AMV products contain the Atmospheric Motion Vectors (AMVs) derived by tracking cloud features in the Brightness Temperature (BT) images of the nadir view in band S8. These data include the speeds, directions, heights and geographical locations of the wind vectors. These measurements are accompanied with tracking and time information, quality indexes and meteorological auxiliary data. - All Sentinel-3 NRT products are available at pick-up point in less than 3h - Sentinel-3 is part of a series of Sentinel satellites, under the umbrella of the EU Copernicus programme.

4. Atenção à estrutura dos dados BUFR

O arquivo decodificado mostra uma característica importante: existem campos repetidos, identificados por #1#, #2#, #3# etc.

Por exemplo, há diferentes grupos de pressão e componentes u e v. Esses grupos não devem ser tratados automaticamente como vetores independentes.

Nesta primeira versão, estou utilizando os campos principais identificados no arquivo:

    #1#latitude e #1#longitude;
    #1#pressure;
    windDirection e windSpeed;
    #1#trackingCorrelationOfVector.

A pressão é convertida de Pa para hPa. A velocidade permanece em m/s.

Referência: estrutura extraída do arquivo amv_decodificado.txt.

Minha recomendação é manter a geração do CSV e acrescentar um arquivo GeoJSON para cada produto BUFR. Assim, teremos os dois formatos, cada um com uma finalidade específica:

    CSV: ideal para análise com Pandas, estatísticas, filtragem e comparação dos dados.
    GeoJSON: ideal para visualização geográfica, integração com mapas Leaflet, QGIS e outras ferramentas GIS.

O GeoJSON é, na realidade, um arquivo JSON com uma estrutura própria para dados geográficos. Por isso, eu o escolheria em vez de um JSON genérico.
1. Estrutura recomendada do GeoJSON

Cada vetor AMV será representado por uma feição geográfica (Feature), com a posição do vento como geometria e os demais dados como propriedades.

Exemplo de um registro:

{
  "type": "Feature",
  "geometry": {
    "type": "Point",
    "coordinates": [-103.94395, -44.63910]
  },
  "properties": {
    "vector_id": 1,
    "pressure_pa": 33260.0,
    "pressure_hpa": 332.6,
    "wind_direction_deg": 309,
    "wind_speed_ms": 44.3,
    "tracking_correlation": 0.717,
    "datetime": "2026-11-12 16:42:38",
    "satellite": 856
  }
}

Um detalhe importante: no GeoJSON, a ordem das coordenadas é longitude, latitude. Portanto, o primeiro valor será -103.94395 e o segundo -44.63910.

5. Dois parâmetros importantes

Correlação mínima: o mapa inicia mostrando todos os vetores. O controle deslizante permite ajustar o limite de correlação entre 0 e 1 e observar quantos vetores permanecem visíveis.

Comprimento das setas: o padrão inicial é 40 km. É apenas uma escala gráfica para facilitar a visualização, não representa a distância efetivamente percorrida pelo vento.

Pode ser alterado na execução:

python src/plot_amv_map.py --arrow-length-km 60

6. Atenção à direção do vento

Na rotina, considerei windDirection como direção meteorológica, ou seja, de onde o vento vem. Por isso, a seta é desenhada no sentido oposto, indicando para onde o vento se desloca.

Essa convenção deve ser confirmada na documentação específica do produto AMV antes de utilizar as setas em análises científicas.
